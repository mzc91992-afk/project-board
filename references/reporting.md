# 项目盘点与汇报口径

把看板数据变成一份可决策的汇报，重点不是罗列，而是**说清变化、指出风险、点名到人**。

## 一、取数原则

1. 每版从数据源重新读取全部字段，不复用上一版结论。
2. 金额单位统一（默认万元）；未填或为 0 写「待定」，不估算、不四舍五入凑整到「约」。
3. 落地月份为空写「未定」，不按「本季度／年底」之类表述推测。
4. `deleted_at` 非空的项目不计入在手；`active` 为推进中，`paused` 为暂缓。
5. 重要度 / 紧急度必须取当前值，禁止沿用上一版。
6. 新版本整体覆盖旧版本，不保留历史差异；仅当用户明确要求对比时，才输出「与上一版比对」。

## 二、三种「没进展」必须分开写

| 状态 | 判定 | 汇报措辞 |
| --- | --- | --- |
| 数据未回填 | 项目行与所有时间线表自某时点起无任何写入 | 「零回填（自 YYYY-MM-DD HH:mm 起 N 天未动）」 |
| 形式 / 薄回填 | 有写入，但只更新了标签或一句话，未回答待决问题 | 「薄回填后无后续，关键问题仍未回答」 |
| 进展为零 | 有记录，但内容显示动作未发生、排期未定 | 「有记录但无实质推进」 |

三者不可混用「无变化」一笔带过——它们对应的管理动作完全不同。

## 三、五段式汇报结构

```
1. 本期变化
   - 新增 / 暂缓 / 恢复：逐项列出，无则写「无」
   - 金额、落地月份、重要度 / 紧急度变动：逐项列出，无则写「无」
   - 新增动态 / 附件 / 进展记录：给出条数与最后一次写入时间
   - 若全表零变化，直接写明「连续第 N 版零变化」及最后一次内容写入时间

2. 在手盘面
   - 推进中 N 个 + 暂缓 M 个
   - 已形成金额口径合计（只累加非空且非 0 的金额，待定项单列不计入）
   - 按业务主线 / 分类给出分布

3. 逾期事项
   | 事项 | 状态 | 下一步 | 责任人 | 时点 |
   状态用 ✅ 闭环 / 🔶 部分或薄回填 / ❌ 零回填 三档，并标注持续版数与天数

4. 本期最需要处理的三件事
   每条包含：事实（deadline、剩余天数）、缺口（哪些动作未回填）、影响（错过什么）、建议动作

5. 资源冲突提示
   - 同一周内的到场、来访、交付、评审等硬性日程
   - 指出冲突窗口，建议提前定人，不替用户做决定
```

## 四、措辞规范

- 用「距今 N 天」而不是「下周」「近期」，避免相对时间歧义。
- 引用 deadline 时同时给出日期与星期，并写明「以数据源记录为准」。
- 客观陈述事实，不用「应该已经」「估计完成」等推测语气。
- 涉及人的地方点名到角色或姓名，不写「相关人员」。
- 结论与建议分开：先给事实判断，再给可选动作，不把建议伪装成事实。

## 五、导出

模板提供两种交付物：

- **明细表 Excel**：所见即所得，保留当前搜索 / 排序 / 筛选后的行与列宽设置。
- **Markdown 汇报**：按原文口径生成，可直接粘贴进周报；生成后应人工复核三段式状态区分与金额口径。
